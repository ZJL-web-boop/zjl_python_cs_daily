# Day 15 - LeetCode 49.字母异位词分组

## 题目

现在给我们一个字符串数组，我们要给其中的字符异位词进行分组，然后以列表的形式返回。

比如，给我们的数组是['abc','cba','','e']，我们要返回[['abc','cba'],[''],['e']]。

## 解法一：利用key为26字母元组的哈希表

思路：其实本题我们要完成两件事，第一是要找出哪些字符串为字符异位词，第二是把他们合并为列表的形式。

如果我们还想像LC242题一样去找字符异位词的话，这道题就比较麻烦了，所以我们应该要求找字符异位词之间的共性所在。

字符异位词所含26个字母中的字母种类和对应的数目是完全一致的，所以我们可以用**26字母的数量元组作为键值、对应的字符异位词列表作为value**去构建哈希表。

代码：

```python
from string import ascii_lowercase # 导入含26个字母（按顺序）的字符串
class Solution(object):
    def groupAnagrams(self, strs):
        dic = {}
        for word in strs: # 构建26字母的数量元组作为键值、对应的字符异位词列表作为value的哈希表
            key = tuple(word.count(c) for c in ascii_lowercase)
            if key in dic:
                dic[key].append(word)
            else:
                dic[key] = [word]
        return list(dic.values()) # 取字典中的value值（小列表）合并为一个大列表
```

- 时间复杂度：O(26 × L)（L 为所有字符串的字符总数——每个词要做 26 次 count，每次 count 都要扫描整个词）
- 空间复杂度：O(L)（L 为所有字符总数，主要开销是结果列表本身要装下全部单词；额外的 key 开销是 O(26 × 组数)）

### 不足之处

每个词都要做 26 次 count，每次 count 又扫描整个词，**常数因子高达 26**。

但要注意措辞：这是**常数大，不是量级差**——渐进复杂度仍然是 O(L) 线性（26 是常数，大 O 记法会吞掉它）。这和 day14 里"删掉终检循环"是同一类优化讨论：**常数因子优化和量级优化是两回事**。

## 解法二：利用排序后的字符元组（字符串）作为键值

思路：解法一是"记录每个词长什么样"（26 个字母各出现几次），解法二换一个角度——**给每个词算一个"签名"**。

字符异位词的本质是构成字符完全相同，那么把它们**按相同规则排序**，得到的字符序列必然完全一致："eat"、"tea"、"ate" 排序后都是 "aet"。所以排序结果（要转成可哈希的元组或字符串，列表不能当 key）可以作为统一的键值。

代码：

```python
class Solution(object):
    def groupAnagrams(self, strs):
        dic = {}
        for word in strs:
            key = tuple(sorted(word)) # 排序后异位词的key完全相同（列表不可哈希，要转成元组）
            if key in dic:
                dic[key].append(word)
            else:
                dic[key] = [word]
        return list(dic.values())
```

- 时间复杂度：O(L × log k)（L 为所有字符总数，k 为单词平均长度；每个词排序 O(k log k)）
- 空间复杂度：O(L)（L 为所有字符总数）

## 两种"指纹"的对比

| | 解法一 · 26 元组计数 | 解法二 · 排序指纹 |
|---|---|---|
| 指纹是什么 | 每个字母各出现几次 | 字符排好序的长相 |
| 时间复杂度 | O(26 × L)，常数 26 | O(L × log k)，常数小 |
| 字符集范围 | **只认 a-z，其他字符当空气** | 任意字符自动进指纹 |
| 适用场景 | 题面限定小写字母时才安全 | 通用，与字符集无关 |

（补充：短单词场景下排序版的实际常数远小于 26，所以跑得更快；只有单词长到几万字符，解法一的线性优势才会反超。）

### 一个暴露差别的实验

输入 `['ab!', 'ab?', 'ba!']`，正确答案是 2 组（`!` 和 `?` 不是同一字符）：

```
解法一（26元组）: [['ab!', 'ab?', 'ba!']]      ← 全塞进一组，错了
解法二（排序）  : [['ab!', 'ba!'], ['ab?']]    ← 正确
```

原因：26 元组只统计 a-z，`!` 和 `?` 根本不进指纹，`'ab!'` 和 `'ab?'` 算出来一模一样，于是被误判成异位词。**LeetCode 49 题面限定"小写字母"，所以两版都能 AC——但那是题面在给解法一兜底，不是解法一本身健壮**。

## 收获

- 学会了分组问题的通解思路：**给每个元素算一个有区分度、可哈希的"签名"，签名相同的归为一组**。这道题的难点不在分组，而在"签名怎么设计"；
- "可哈希"的具象化：列表不可哈希，所以要把排序结果转成元组（或字符串）才能当 key；
- 巩固了"常数因子 vs 渐进量级"的区分（解法一常数大但仍是线性，见 day14 同款讨论）；
- 踩过一个坑：循环变量取名 `str` 会遮蔽 Python 内置的 `str` 类型，代码能跑但以后在函数内用 `str()` 转换就会报错。**循环变量别用内建名**（str/list/dict/sum...）；
- 掌握了取字典全部 value 的写法：`list(dic.values())`，不用手写循环 append。
