# Day 16 - LeetCode 349.两个数组的交集 & 387.字符串中的第一个唯一字符

# 一、LeetCode 349.数组的交集

## 题目

给我们两个整数数组，我们要同样以列表的形式返回它们的交集。注意相同的元素即使两数组中各有多个，交集中只能保留一个。

## 解法一：哈希表+计数

思路：其实这道题也能用哈希表解决，我们构建一个以其中一个数组的元素为key，对应的数量为value的字典，然后去遍历另一个数组，

但是我们当遇到字典中已有的元素时，要直接把库存清空，这样才能保证交集数组中不会有重复的元素出现。

代码：

```python
class Solution(object):
    def intersection(self, nums1, nums2):
        dic = {}
        for num in nums1: # 构建一个哈希表：nums1中的元素为key，其对应的数量为value
            if num in dic:
                dic[num] += 1
            else:
                dic[num] = 1
        lis = [] # 用来存放最后的交集元素
        for num in nums2:
            if dic.get(num, 0) > 0: # 如果num是二者共有的，且是第一次在循环遍历中出现，才能满足这个判定条件
                lis.append(num)
                dic[num] = 0 # 确保相同的元素只存一个，只要第一个存了，就清空库存
        return lis
```

- 时间复杂度：O(N+M)（N、M分别是数组nums1、nums2的长度）
- 空间复杂度：O(N)（N是数组nums1的长度）

### 注意点

这里的计数其实大部分是无效的，因为这道题只在乎有还是没有，不在乎到底有多少。

## 解法二：集合去重+集合交集 & 运算

思路：由于这道题只在乎有还是没有，所以我们可以直接对两个数组转换为集合实现去重操作，然后使用集合求交集 & 运算即可解决问题。

代码：

```python
class Solution(object):
    def intersection(self, nums1, nums2):
        return list(set(nums1) & set(nums2)) # 使用集合去重和集合的交集运算
```

- 时间复杂度：O(N+M)（N、M分别是数组nums1、nums2的长度）
- 空间复杂度：O(N+M)（N、M分别是数组nums1、nums2的长度），这种解法是牺牲了空间复杂度的

## 收获

- 解法一的库存操作从 350 的‘减一’变成 349 的‘清零’——350 要维护数量，349 只维护存在性，操作随信息需求降级；

## 待复习

- `set(nums1) & set(nums2)` 里 `&` 这一步的复杂度是多少？为什么 CPython 实现时选择遍历较小的那个集合？（提示：单次哈希查找平均 O(1)，成本 = 被遍历集合的大小；min(n,m)，被两侧建表的 O(n)+O(m) 盖住后整体记 O(n+m)）
- 同样输入 `[1,2,2,1]` 和 `[2,2]`，为什么 350 返回 `[2,2]` 而 349 返回 `[2]`？用"问题需要的信息量决定指纹的有损程度"一句话说清（350 需要数量→dict 计数；349 只需要存在性→set；49 的 26 元组 vs 排序是同一母题）
- 为什么 v2（一行版）每次运行输出的顺序可能不一样？LeetCode 为什么不管顺序？（set 无序；哈希决定存储位置。联想：计算器 v1 里 set 菜单打印顺序漂移，同一个原因）
- 解法一里"清空库存"（`dic[num] = 0`）换成"从字典里删除这个键"（`del` / `pop`）行不行？两种写法的"库存为 0"和"键不存在"语义如何统一？（提示：`get(num, 0)` 的默认值让两种状态等价）


# 二、LeetCode 387.字符串中的第一个唯一字符

## 题目

给定一个字符串，我们要找其中第一个在该字符串只出现过一次的字符，如果有的话就返回对应下标，没有就返回-1。

## 解法：哈希表+计数

思路：构建一个哈希表，其中字符为key，对应的出现次数为value，然后寻找第一个value为1的字符，有则返回其索引下标，没有的话就返回-1。

代码：

```python
class Solution(object):
    def firstUniqChar(self, s):
        dic = {}
        for c in s: # 构建哈希表：s中的字符为key，对应的数量为value（注意这个过程是按照字符串中字符出现的先后顺序构建的）
            if c in dic:
                dic[c] += 1
            else:
                dic[c] = 1
        for i, v in dic.items(): # 在字典中查询第一个对应value值为1的元素
            if v == 1:
                return s.find(i)  # 找到指定元素，返回对应的索引下标
        return -1 # 字符串中没有唯一的元素
```

- 时间复杂度：O(n)（n为字符串s的长度）
- 空间复杂度：O(n)（n为字符串s的长度）

### 解法缺陷

此思路是**基于在构建字典时是按照字符串中字符出现的先后顺序进行的，即默认字典是有序的**，这样后续的for循环才有可能找到第一个对应value值为1的元素，

但是这只是适用于Python 3.7+的版本，对于之前的Python版本是不适用的（之前的版本中字典是无序的），所以我们能不能优化一下，解决这一语言局限问题呢？

优化后的代码:

```python
class Solution(object):
    def firstUniqChar(self, s):
        dic = {}
        for c in s: # 构建哈希表：s中的字符为key，对应的数量为value
            if c in dic:
                dic[c] += 1
            else:
                dic[c] = 1
        for i, c in enumerate(s): # 按照字符串原先的顺序从左到右遍历，不需要考虑字典有没有序的问题（解决了版本1的语言限制问题）
            if dic[c] == 1:
                return i
        return -1 # 字符串中没有唯一的元素
```

- 时间复杂度：O(n)（n为字符串s的长度）
- 空间复杂度：O(n)（n为字符串s的长度）

### 优化点

**把原先对字典进行遍历的操作改成对原字符串s的遍历操作**，这样最后得到的就自然而然是第一个唯一的元素。

## 收获

- 实现了从“能想出解法解决问题”到“分析该解法的局限性”最后到“优化解法消除局限性”的闭环；
- 又见“正确性摆在明面 vs 藏在不变量里”的选择题：v1 的正确性藏在“dict 有序”这个语言契约里（隐式），v2 的正确性写在“按字符串原序遍历”这个动作里（显式）——和 242 的终检版/守恒版是同一个取舍。

## 待复习

- v1（扫 dict 版）为什么在 Python 3.7+ 是对的？用一句话说清“两序合一”：dict 的插入序 = 字符首次出现序，而唯一字符的首次出现就是它唯一一次出现，所以 dict 里唯一 key 的先后顺序 = 它们在字符串里的下标顺序；
- 把 v1 原样搬到 Java（HashMap 无序）会发生什么？可能返回一个“存在但不是第一个”的唯一字符——正确性依赖语言契约的代码不可移植；
- v1 里的 `s.find(i)` 多付出了什么？为什么 v2 不需要？（find 要再扫一遍字符串找下标 O(n)；enumerate 遍历时白送下标，一次循环拿齐“顺序+字符”）
- 空间复杂度彩蛋：LeetCode 限定小写字母 → dict 最多 26 个键 → 严格说是 O(1)，和 383 的“O(n) 上界 vs O(1) 实际”是同一套讨论——写 O(n) 不扣分，口头能说出 O(1) 是加分。
