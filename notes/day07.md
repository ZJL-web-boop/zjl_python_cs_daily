# 一、LeetCode 66. 加一

## 题目

用一个列表表示一个大整数，比如[1,2,3]表示123，注意列表中不含任何无意义的前导零，如123不能表示为[0,1,2,3]；
现在这个整数加一，返回以列表形式表示的结果。比如，[9,9] → [1,0,0]

## 解法一：字符串法（工具解）

思路：如题意我们可以先把整数数组转换为对应的整数，加1后又把它转换为整数数组的形式，这一过程涉及许多内置表达的使用：

- 首先整数数组是较难直接转换为整数，我们先得把它转换为字符串，再把字符串转换为整数

```
# 列表变为字符串要用.join函数，但这个函数只能对字符串数组进行操作，故我们得先把整数数组转换为字符串数组
lis = [1,2,3]
lis1 = [str(i) for i in lis] # 整数数组转换为字符串数组的第一种方法：对列表中的每一个元素进行转换
lis2 = list(map(str,lis)) # 整数数组转换为字符串数组的第二种方法：使用map()函数，但外面注意要用list套住，否则返回的只是map对象
s = ''.join(lis1) # 将字符串数组转换为字符串：['1','2','3'] → '123'，注意''.join这个引号中填啥就用啥连接各元素
n = int(s) # 将字符串转换为整数
```

- 然后我们加一后再把整数先转换为字符串，再转换为字符串数组，最后转换为整数数组返回

```
s1 = str(n+1) # 将整数转换为字符串
lis3 = list(s1) # 将字符串转换为字符串数组
lis4 = [int(c) for c in lis3] # 将字符串数组转换整数数组的第一种方法
lis5 = list(map(int,lis3)) # 将字符串数组转换整数数组的第二种方法
```

代码：
```python
"""第一版主要是使用列表与字符串之间的转换、
整数数组和字符串数组之间的转换解决这一问题
"""
class Solution(object):
    def plusOne(self,digits):
        s_digits = [str(x) for x in digits] # 首先先把整数数组转化为字符串数组，因为后续使用的.join函数只能接受字符串元素
        num = int(''.join(s_digits)) # 把字符串数组先变成字符串，再强制类型转换变成整数
        new_digits = list(str(num + 1)) # 整数先加1，然后变为字符串，最终转化为列表（即字符串数组）
        return [int(i) for i in new_digits] # 把字符串数组转变为整数数组
```

时间复杂度：O(n)，其中n为整数数组的长度

## 解法二：递归法

思路：其实我们仔细想想，当整数的个位数字 < 9时我们只需要把个位数字加1即可；
当个位数字等于9时，加1就得考虑进位了，相当于个位变为0，去掉个位的部分要加1，
那我们就可以把这个去掉个位的部分看成一个新的整数，它加1相当于就是再调用一次这函数，即用递归思想使解决这个问题，
最后 新列表+[0] 两列表相加得到最终结果。

代码：

```python
"""第二版主要是使用了递归的思路解决这一问题
"""

class Solution(object):
    def plusOne(self, digits):
        length = len(digits) # 记录整数数组的长度
        if not digits: # 列表为空时
            return [1]
        if digits[-1] < 9:
            digits[-1] += 1
            return digits
        else: # 列表最后一个元素为9，大整数+1后末位变为0，剩余部分的变化我们可以视为：对原来去掉最后一位的新整数加1的操作
            lis = digits[:]
            lis.pop()
            return self.plusOne(lis) + [0] # 递归调用

```

时间复杂度：最坏 O(n²)，其中 n 为整数数组的长度（全为 9 时最坏）；空间复杂度 O(n)（递归栈 + 每层的拷贝列表）

乍一看每层递归只做一点点事，像 O(n)，但成本藏在两个"看不见的地方"：

- **`digits[:]` 切片拷贝**：切片不是引用，会真的把所有元素复制一遍。第 0 层复制 n 个、第 1 层复制 n-1 个……下潜到空列表总共约 n²/2 次复制
- **`self.plusOne(lis) + [0]` 拼接**：`+` 的语义是"造一个**新**列表，把两边元素全部复制进去"，不是原地追加。回溯阶段 `[1]+[0]` 复制 2 个，再 `+[0]` 复制 3 个……又是约 n²/2 次

递归深度本身是 O(n)，但每层的拷贝 + 拼接都是 O(n)，所以总时间是 O(n²)。n ≤ 100 时实际无感，但面试要能说清。

对比迭代版为什么是 O(n)：迭代全程在原列表上**原地修改**（`digits[i] = 0` 是 O(1) 赋值，`insert(0,1)` 最多一次 O(n)），没有"复制整个列表"的动作。这和"`result = result + [0]` 每次复制整个 result（循环 n 次成 O(n²)）"vs"`result.append(0)` 均摊 O(1)"是同一对经典性能陷阱——反复拼接用 `+`，往尾巴加用 `append`。

### 注意：递归必须要有递归终止条件 —— if not digits: return [1] 等

## 解法三：迭代法（从右往左找第一个 <9 的位）

思路：其实我们可以直接对列表从右往左进行迭代：找第一个小于9的位置，因为在这个位置的右边都是9，最后都会变为0，
所以我们只需要把第一个小于9的位置上的数加1，如果没有小于9的数，则在列表前添加一个1。

代码：

```python
"""第三版主要是采用对列表内的各元素从右往左进行逐位进位的操作
"""

class Solution(object):
    def plusOne(self,digits):
        i = len(digits)-1 # 最后一个索引下标
        if digits[i] < 9: # 不需要进位操作
            digits[i] += 1
            return digits
        while i>=0 and digits[i]==9: # 末位为9的情况
            digits[i] = 0
            if i == 0: # 比如把[9]变成[10]，要向表头新增一个1
                digits.insert(0,1)
                break
            elif digits[i-1] < 9: # 不需要进位操作
                digits[i-1] += 1
                break
            else: #索引为i-1的项值为9且i > 0，现在我们要对这项之前的项进行加1操作
                i = i-1
        return digits
```

时间复杂度：O(n)，n 为整数数组的长度

另一种写法：循环里只做"是 9 就置 0 继续、不是 9 就 +1 返回"，循环走完说明全是 9，直接 return [1] + digits——把"全 9"这个特例从循环内的分支赶到循环外统一处理，循环退出后只剩一种情况，收尾不需要判断（"消灭特例"主题第三次出现：罗马数字 → LC58 → 这里）。

标准版代码：

```python
"""标准解：从右往左找第一个 <9 的位，循环退出则说明全是 9
"""

class Solution(object):
    def plusOne(self,digits):
        for i in range(len(digits)-1, -1, -1): # 从个位（最后一位）往高位走
            if digits[i] < 9: # 遇到第一个小于9的位：直接加1收工，它右边的9在之前的循环里已被置0
                digits[i] += 1
                return digits
            digits[i] = 0 # 这位是9：置0，继续进位（留给下一轮循环处理更高位）
        return [1] + digits # 循环能走完说明每一位都是9（如[9,9,9]），最高位补1，如[1,0,0,0]
```

对比我的解法三：标准版把"全 9"作为循环退出后的唯一剩余情况统一处理，不需要 `if i == 0` 这样的特判分支；我的版本把"全 9"放进 while 里用 `insert(0,1)` 显式处理，分支更多但每步画面感更直观。两种都是 O(n)。

# 二、LeetCode 69. x 的平方根

## 题目

给你一个非负整数 x，计算并返回 x 的算术平方根。由于返回类型是整数，结果只保留整数部分，小数部分将被舍去。注意：不允许使用任何内置指数函数和算符，例如 pow(x, 0.5) 或者 x ** 0.5。比如 x = 8 → 返回 2（8 的算术平方根是 2.82842...，截断小数部分）。

## 解法一：内置函数（工具解）

思路：题目本意是考察手写算法，但 Python 一行就能解决——pow(x, 0.5) 求 x 的 0.5 次方即开平方，结果是小数，用 int() 强制类型转换截断小数部分即可。

代码：

```python
class Solution(object):
    def mySqrt(self, x): # 题目要求：求非负整数的算术平方根（结果只保留整数部分，小数部分被截断）
        return int(pow(x,0.5)) # python的内置函数pow(x,i):求x的i次方，注意要int强制类型转换
```

时间复杂度：O(1)（内置函数视为常数时间，实际内部实现远比我们的手写算法复杂）

注意：如果用 C++/Java，pow 返回的是浮点数（签名是 `double pow(double, double)`，传整数进去也会先转 double），且不保证末位舍入正确。x = 2147395599 = 46340² − 1 时，真实平方根是 46340.99999998…，紧贴 46341 这条整数边界——pow 舍入一旦越线返回 46341.0，`(int)` 截断（不是四舍五入）后就得到差 1 的错误答案。注意丢精度不是发生在"存 x"这步（x ≈ 2.1×10⁹ 远小于 double 的精确表示上限 2⁵³ ≈ 9×10¹⁵），而是发生在"算完开方后最后一步舍入"。Python 能过是"int 任意精度 + 底层开方舍入可靠"的运气，不是语言保证——x 超过 2⁵³ 后 `int(x**0.5)` 照样会翻车，彻底免疫的方法是全程整数运算（math.isqrt 或解法三的二分）。

## 解法二：线性扫描（双边夹逼）

思路：我们实际上要找的是"不大于 x 的算术平方根的最大整数"。这个定义可以翻译成一个双边夹逼条件：i*i <= x < (i+1)*(i+1)，即 i 的平方不超过 x，但 (i+1) 的平方已经超过 x。从 0 开始逐个尝试，命中条件就 break，此时 i 就是答案。x = 0 时 0 <= 0 < 1 直接成立，边界自然覆盖。

代码：

```python
""" 第二版：我们假设不能使用python内置函数pow或运算x**0.5，
我们应该采取的算法（一）如下
"""

# 此算法的时间复杂度为O(√x)，效率还是比较低的

class Solution(object):
    def mySqrt(self, x): # 题目要求：求非负整数的算术平方根（结果只保留整数部分，小数部分被截断）
        i = 0
        while i <= x: # 暴力遍历方法
            if i * i <= x < (i + 1) * (i + 1): # 注意这个判断条件，我们实际上是要不大于x的算术平方根的最大整数
                break
            i += 1
        return i
```

时间复杂度：O(√x)——答案最大是 √x，最坏要从 0 试到 √x；空间 O(1)

实测对比：x 取 int 最大值 2147483647 时，答案 46340，线性扫描要循环 46341 次。

## 解法三：二分查找

思路：解法二慢在"一个一个试"。但答案显然在 0 ~ x 之间有序排列（i 越大 i*i 越大），有序 + 范围查找正是二分的主场：每次取区间中点 mid，用 mid*mid 和 x 比大小，把区间砍掉一半。命中条件沿用解法二的双边夹逼 mid*mid <= x < (mid+1)*(mid+1)，但砍半的威力是指数级的。

注意二分并不是"利用了树这种数据结构"，它只靠"每次砍半"这个动作——只是决策过程可以画成一棵二叉树来想象，所以才说复杂度是 O(log x)（n 个元素砍半到只剩一个只需 log₂n 次）。

代码：

```python
""" 第三版：第二版暴力遍历的时间复杂度还是太大了，
所以我们这里采用效率较高的二分法解决这一问题
"""

""" 二分算法本质上是依靠"每次砍半"这个动作，决策过程可以画成一棵二叉树来想象，时间复杂度为O(log₂(x))。
当x比较大时，使用此算法解决问题效率大幅提升。
"""

class Solution(object):
    def mySqrt(self,x): # 题目要求：求非负整数的算术平方根（结果只保留整数部分，小数部分被截断）
        left = 0 # 定义区间的左边界，从0开始往大走
        right = x # 定义区间的右边界，从x开始往小走
        ans = 0 # ans这个临时变量用来存放最终的答案，其初始值没有什么具体的含义
        while left <= right:
            mid = left + (right - left) // 2 # 每次都用区间中点的值去计算和比较
            if mid * mid <= x < (mid + 1) * (mid+1):
                ans = mid
                break
            elif mid * mid > x: # 目标值在mid的左边，则更新区间的右边界
                right = mid - 1
            else: # 目标值在mid的右边，则更新区间的左边界
                left = mid + 1
        return ans
```

时间复杂度：O(log x)——每次循环区间砍半；空间 O(1)。同样取 x = 2147483647，只需循环 31 次（46341 次 → 31 次，这就是对数级别的威力）

两个二分的经典细节：

- **`left + (right - left) // 2` 是防溢出的标准写法**。在 Python 里 `(left + right) // 2` 完全等价（整数任意精度），但 C++/Java 中 left + right 可能超过 int 上限溢出成负数，面试写二分时这个细节是加分项
- **`mid * mid <= x < (mid+1)*(mid+1)` 是"命中式"判断**：条件是答案的精确定义，命中当场记录并 break。还有一种"记录式"写法：只判断 `mid*mid <= x` 这一半，成立就 `ans = mid; left = mid + 1`（mid 可能是答案，继续往右找更大的），否则 `right = mid - 1`，循环结束 return ans——不需要精确的命中条件，更通用，遇到"找最后一个满足条件的数"且条件没有闭式表达时只能用它

## 收获

- 先想清楚"整数平方根"的精确定义（双边夹逼），把定义直接翻译成判断条件，线性版和二分版共用同一个条件——定义清楚了，算法只是换遍历方式
- 线性 46341 次 vs 二分 31 次：**有序 + 范围查找就上二分**，"砍半"的力量是对数级的。这个套路和猜数字游戏"大了往小猜、小了往大猜"同源，但每次取中点才是最优策略
- off-by-one 在二分里的形态：如果更新写成 `left = mid`（不是 mid+1）配上向下取整的 mid，当区间缩到 [lo, lo+1] 时 mid = lo，left 不动，区间永远不缩小——死循环。正确姿势是保证每次循环区间至少收缩 1
